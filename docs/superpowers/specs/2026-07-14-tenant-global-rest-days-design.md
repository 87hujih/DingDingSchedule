# 租户级每周全体休息日设计

## 1. 目标

管理员可在“作息与考勤设置”中为每个租户选择每周任意多个全体休息日。命中所选星期时，系统完全停止当日考勤，不生成新考勤记录、不计算人员统计、不查询钉钉打卡，也不发送考勤或迟到通知。

配置仅影响保存后的新考勤执行，不追溯改写历史快照、补签结果或排名。

## 2. 非目标

- 不取消或批量改写现有个人休息日。
- 不增加按具体日期、法定节假日或临时调休的日历配置。
- 不在配置变更后删除或重算既有考勤记录。
- 不将全体休息日与“考勤总开关”或“个人休息日参与考勤”开关合并。

## 3. 数据模型

`schedule_settings` 增加 `global_rest_days VARCHAR(20) NOT NULL DEFAULT ''`。Go 模型字段名为 `GlobalRestDays string`。

存储格式为逗号分隔的规范化星期数字：

- `1` 代表周一，`7` 代表周日。
- 允许多选，例如 `1,6,7`。
- 保存时仅接受 `1..7`，去重并升序排列。
- 空字符串表示未设置全体休息日。
- 读取到非法格式时返回错误，不默认为工作日继续考勤。

选择单列 CSV 是因为可选值固定为七个，且 GoAdmin v1.2.26 原生支持将多选值写入单列。关联表会引入不必要的 CRUD 和事务复杂度；位掩码则不利于后台排障和人工查看。

## 4. 管理后台

在现有“作息与考勤设置”列表和表单中增加“全体休息日”：

- 表单使用 `CheckboxStacked` 展示周一至周日七个选项，可任意多选和全部清空。
- 编辑回显时将 CSV 拆分为多选值。
- 提交时对值域、重复值和顺序进行规范化。
- 列表将 `1,6,7` 显示为“周一、周六、周日”，空值显示“未设置”。
- 帮助文案为“所选星期全体停止考勤；留空表示不设置”，与个人休息日开关明确区分。

管理后台直接维护 `schedule_settings`，现有租户权限和租户选择方式保持不变。

## 5. 统一停考策略

新增独立的租户考勤日历策略，集中解析配置并提供：

```go
IsGlobalRestDay(ctx context.Context, date time.Time) (bool, error)
```

策略从当前租户的 `schedule_settings` 读取配置，统一使用 `scheduleutil.WeekdayMon1Sun7` 计算星期，避免 Go `time.Weekday` 的周日为 0 语义泄漏到业务层。

全体休息日是强制停考规则，优先级高于课表、请假、个人休息日和个人休息日开关。它不依赖 `rest_day_attendance_enabled`。

未找到租户设置时，按空配置处理，与现有默认行为兼容。数据库其他错误或配置格式错误时，将错误向上返回；自动调度将终止当次执行并记录错误，手动查询则返回业务错误。

## 6. 执行流程

### 6.1 自动初次考勤

调度器在检查租户考勤总开关后、查询租户、学期周次或钉钉打卡之前判断全体休息日。命中时记录可观测的 skip 日志并立即返回，不调用考勤详情、保存、群推送或迟到提醒。

cron 任务仍按时段注册，但每次回调会用策略早退。不将星期编译进 cron 表达式，因为这会增加配置热更新和任务重建的复杂度，且不会改变对外行为。

### 6.2 自动最终结算

最终结算入口执行同样的策略判断。命中时不查询钉钉数据、不生成最终快照，也不发送群消息。

### 6.3 实时查询和手动触发

所有会新计算当日考勤的 service 入口在任何人员、课表、请假或打卡查询之前调用统一策略。命中时返回稳定的业务错误码与文案：

> 今天是全体休息日，已停止考勤

管理员手动触发不能绕过 service 层规则，不得落库或发送通知。

### 6.4 历史读取

查询已存在的历史快照时不动态应用当前全体休息日配置。因此，管理员新增或删除某个星期后，既有记录、排名和分析结果保持不变。

## 7. API 与返回语义

本期不新增独立的全体休息日 API，管理后台依照现有 GoAdmin 表单直接维护字段。`GET /api/schedule/info` 的返回结构增加 `global_rest_days []int`，数组按星期升序返回，便于其他客户端读取当前配置，但不提供写接口。

新增 `ErrGlobalRestDay()` 快捷错误，复用 `CodeStatusInvalid` (`30004`)，并使用文案“今天是全体休息日，已停止考勤”。实时查询和手动写入入口均使用该错误，不返回伪造的应到 0 人考勤结果。

## 8. 数据迁移与兼容

GORM `AutoMigrate` 在启动时添加新列，默认空字符串使所有现有租户的行为保持不变。不执行历史回填。

回滚应先在管理后台清空所有租户的 `global_rest_days`，再回滚应用版本。保留数据库列不影响旧版代码；若必须删列，应在确认无新版实例运行后单独执行数据库变更。

## 9. 可观测性和错误处理

自动调度命中全体休息日时记录结构化 INFO 日志，包含 `tenantId`、`date`、`weekday` 和 `action=skip_global_rest_day`，不包含人员或打卡数据。

配置读取失败或格式非法时：

- 自动调度记录 ERROR 并终止当次执行。
- 实时查询和手动触发返回内部业务错误。
- 不将解析失败当作“未设置休息日”继续执行。

## 10. 测试策略

### 10.1 规则单测

- 表驱动验证空值、单选、多选、周日、非法数字、重复值和非法格式。
- 验证不同租户配置隔离。
- 验证 Asia/Shanghai 时区下的周日 00:00 和周一 00:00 边界。
- 验证全体休息日不受个人休息日开关影响。

### 10.2 后台表单测试

- 验证多选提交被规范化为升序 CSV。
- 验证空选项可清除旧配置。
- 验证非法星期不能入库。
- 验证列表文案和编辑回显。

### 10.3 考勤服务测试

- 命中全体休息日时，实时查询返回明确业务错误，且不查课表、请假、个人休息日或钉钉打卡。
- 手动触发和最终结算不写入 `attendance_records`。
- 非全体休息日继续使用现有人员分类和打卡判定。
- 已存历史记录在后续启用对应星期后仍可正常读取。

### 10.4 调度和通知测试

- 初次考勤和最终结算在全体休息日均早退。
- 早退时不查询钉钉、不保存、不推送群消息且不发送迟到提醒。
- 非休息日的调度回调行为保持不变。

## 11. 验收标准

1. 管理员可在租户作息设置中选择、修改或清空周一至周日任意多个全体休息日。
2. 所有租户数据严格隔离，一个租户的配置不影响其他租户。
3. 命中的日期不产生新考勤记录、人员统计、钉钉查询、群推送或迟到通知。
4. 实时查询和手动触发返回“今天是全体休息日，已停止考勤”。
5. 全体休息日不受个人休息日开关影响。
6. 配置变更不改写已存考勤快照、补签、排名或分析结果。
7. 现有租户在迁移后默认为未设置全体休息日，原考勤行为不变。
8. 配置非法或读取失败时安全终止新考勤计算，不会误报全体缺勤。
