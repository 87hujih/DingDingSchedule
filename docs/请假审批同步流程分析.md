# 请假审批同步流程分析

## 概述

本文档详细分析了从钉钉审批事件推送到请假信息入库的完整流程。系统通过钉钉Stream模式接收审批事件，调用钉钉API获取详情，解析表单数据，并最终存储到本地数据库。

## 核心组件详解

### 1. StreamClient - 事件监听器

**文件位置**: `pkg/dingtalk/stream.go`

**职责**:
- 建立与钉钉服务器的Stream连接
- 监听钉钉推送的审批事件
- 过滤LEAVE类型的审批事件
- 触发事件处理回调

**关键代码**:
```go
// handleEvent 处理钉钉事件
func (s *StreamClient) handleEvent(ctx context.Context, df *payload.DataFrame) (*payload.DataFrameResponse, error) {
    var evt bpmsEvent
    if err := json.Unmarshal([]byte(df.Data), &evt); err != nil {
        return payload.NewSuccessDataFrameResponse(), nil
    }

    // 处理请假审批事件
    if s.onBpmsEvent != nil && evt.ProcessInstanceID != "" && evt.ApproveType == "LEAVE" {
        go func() {
            if err := s.onBpmsEvent(context.Background(), s.corpID, evt.ProcessInstanceID, evt.Status); err != nil {
                s.logger.Errorw("处理审批事件失败", "processInstanceId", evt.ProcessInstanceID, "err", err)
            }
        }()
    }

    return payload.NewSuccessDataFrameResponse(), nil
}
```

**事件结构**:
```go
type bpmsEvent struct {
    ApproveType       string `json:"approveType"`       // LEAVE=请假
    ProcessInstanceID string `json:"processInstanceId"` // 审批实例ID
    ProcessCode       string `json:"processCode"`       // 流程编码
    Status            string `json:"status"`            // start/finish/terminate
    EventID           string `json:"eventId"`           // 事件ID
}
```

**特点**:
- 异步处理：使用goroutine处理事件，避免阻塞Stream连接
- 自动重连：连接断开后自动重启
- Panic恢复：捕获panic确保服务稳定

### 2. LeaveSyncService - 同步服务

**文件位置**: `internal/service/leave_sync_service.go`

**职责**:
- 接收审批事件通知
- 调用钉钉API获取审批详情
- 解析表单字段
- 查找本地用户信息
- 构建数据模型并入库

**核心方法**: `SyncProcessInstance`

**处理流程**:

#### 步骤1: 获取租户和客户端
```go
tenant, client, err := s.dingMgr.GetByCorpID(ctx, corpID)
```
- 根据corpID查找对应的租户
- 获取该租户的钉钉API客户端

#### 步骤2: 调用钉钉API获取审批详情
```go
pi, err := client.GetProcessInstance(ctx, processInstanceID)
```
- 调用钉钉API获取完整的审批实例数据
- 包含审批状态、表单字段、发起人等信息

#### 步骤3: 解析表单字段
```go
startAt, endAt, reason, leaveType, err := s.parseLeaveFormFields(pi.FormValues)
```

**支持的表单格式**:

1. **钉钉DDHolidayField组件** (推荐格式):
```json
{
  "name": "[\"开始时间\",\"结束时间\"]",
  "value": "[\"2026-01-06 13:51\",\"2026-01-06 13:52\",0.02,\"hour\",\"事假\",\"请假类型\"]"
}
```
- value数组索引0: 开始时间
- value数组索引1: 结束时间
- value数组索引4: 请假类型

2. **普通表单字段**:
- 开始时间: `start_time`, `starttime`, `开始时间`, `请假开始时间`
- 结束时间: `end_time`, `endtime`, `结束时间`, `请假结束时间`
- 请假理由: `reason`, `leave_reason`, `请假理由`, `事由`, `请假事由`
- 请假类型: `leave_type`, `leavetype`, `请假类型`, `类型`

**时间解析**:
支持多种时间格式:
- `2006-01-02 15:04:05`
- `2006-01-02T15:04:05`
- `2006-01-02 15:04`
- `2006-01-02`
- RFC3339格式
- 时间戳（毫秒/秒）

#### 步骤4: 查找本地用户
```go
dingUserID := strings.TrimSpace(pi.OriginatorUserID)
var userID uint
var userName string
if dingUserID != "" {
    user, err := s.userRepo.FindByDingUserID(ctx, dingUserID)
    if err == nil && user != nil {
        userID = user.ID
        userName = user.Name
    }
}
```
- 通过钉钉用户ID查找本地用户
- 获取本地用户ID和姓名
- 如果找不到用户，userID和userName为空值（不阻断流程）

#### 步骤5: 构建数据模型
```go
rec := &model.LeaveApproval{
    TenantID:          tenant.ID,
    ProcessInstanceID: pi.ProcessInstanceID,
    ProcessCode:       pi.ProcessCode,
    DingUserID:        dingUserID,
    UserID:            userID,
    UserName:          userName,
    StartAt:           startAt,
    EndAt:             endAt,
    LeaveType:         leaveType,
    Reason:            reason,
    ApproveStatus:     normalizeStatus(pi.Status),
    Result:            normalizeResult(pi.Result),
}
```

**状态归一化**:
- `RUNNING`: 审批中
- `COMPLETED`: 审批完成
- `TERMINATED`: 已终止/取消

**结果归一化**:
- `agree`: 同意
- `refuse`: 拒绝
- `cancel`: 撤销

#### 步骤6: 幂等入库
```go
ctxWithTenant := tenantctx.WithTenantID(ctx, tenant.ID)
if err := s.leaveRepo.UpsertByProcessInstanceID(ctxWithTenant, rec); err != nil {
    return errs.WrapMsgErr("leave_sync: 落库失败", err)
}
```
- 使用tenant context确保多租户隔离
- 调用repository层进行幂等写入

### 3. DingTalk Client - API客户端

**文件位置**: `pkg/dingtalk/approval.go`

**职责**:
- 封装钉钉审批API调用
- 处理AccessToken获取
- 解析API响应数据
- 兼容不同版本的API响应格式

**核心方法**: `GetProcessInstance`

**API调用**:
```go
url := fmt.Sprintf("%s?access_token=%s", getProcessInstanceURL, token)
reqBody := map[string]string{"process_instance_id": processInstanceID}
respBody, err := c.postJSON(ctx, url, reqBody)
```

**API地址**: `https://oapi.dingtalk.com/topapi/processinstance/get`

**响应数据结构**:
```go
type ProcessInstance struct {
    ProcessInstanceID string                           // 审批实例ID
    ProcessCode       string                           // 流程编码
    Title             string                           // 审批标题
    Status            string                           // 审批状态
    Result            string                           // 审批结果
    OriginatorUserID  string                           // 发起人钉钉ID
    FormValues        []ProcessInstanceFormComponentValue // 表单字段
    Raw               json.RawMessage                  // 原始JSON
}
```

**兼容性处理**:
- 支持多种字段名变体（驼峰/下划线）
- 兼容不同版本的API响应格式
- 保留原始JSON用于排障

### 4. LeaveApprovalRepository - 数据访问层

**文件位置**: `internal/repository/leave_approval_repository.go`

**职责**:
- 封装数据库操作
- 实现幂等写入逻辑
- 提供查询接口

**核心方法**: `UpsertByProcessInstanceID`

**幂等写入实现**:
```go
return r.db.WithContext(ctx).
    Clauses(clause.OnConflict{
        Columns: []clause.Column{
            {Name: "tenant_id"},
            {Name: "process_instance_id"},
        },
        DoUpdates: clause.AssignmentColumns([]string{
            "process_code",
            "ding_user_id",
            "user_id",
            "user_name",
            "start_at",
            "end_at",
            "leave_type",
            "reason",
            "approve_status",
            "result",
            "raw_instance_json",
            "raw_form_json",
            "updated_at",
        }),
    }).
    Create(rec).Error
```

**幂等性保证**:
- 使用 `(tenant_id, process_instance_id)` 作为唯一键
- 如果记录已存在，更新所有业务字段
- 如果记录不存在，插入新记录
- 支持钉钉重复/乱序回调

**查询方法**:

1. `ListOverlappingByDingUserIDs`: 查询多个钉钉用户在时间窗口内的请假记录
2. `ListOverlappingByUserID`: 查询单个本地用户在时间窗口内的请假记录

**时间重叠查询**:
```sql
WHERE start_at < ? AND end_at > ?
```
- 用于判断请假时间是否与课节时间重叠

### 5. LeaveApproval - 数据模型

**文件位置**: `internal/model/leave_approval.go`

**表名**: `leave_approvals`

**字段说明**:

| 字段 | 类型 | 说明 | 索引 |
|------|------|------|------|
| id | uint | 主键 | PRIMARY |
| tenant_id | uint | 租户ID | 唯一索引、复合索引 |
| process_instance_id | string | 审批实例ID | 唯一索引 |
| process_code | string | 流程编码 | 普通索引 |
| ding_user_id | string | 钉钉用户ID | 复合索引 |
| user_id | uint | 本地用户ID | 复合索引 |
| user_name | string | 请假人姓名 | - |
| start_at | time.Time | 请假开始时间 | 复合索引 |
| end_at | time.Time | 请假结束时间 | 复合索引 |
| leave_type | string | 请假类型 | - |
| reason | text | 请假理由 | - |
| approve_status | string | 审批状态 | 普通索引 |
| result | string | 审批结果 | 普通索引 |
| raw_instance_json | longtext | 原始实例JSON | - |
| raw_form_json | longtext | 原始表单JSON | - |
| created_at | time.Time | 创建时间 | - |
| updated_at | time.Time | 更新时间 | - |
| deleted_at | time.Time | 软删除时间 | 普通索引 |

**唯一索引**:
- `uniq_tenant_pi`: (tenant_id, process_instance_id) - 确保幂等性

**复合索引**:
- `idx_tenant_user_time`: (tenant_id, user_id, start_at, end_at) - 按本地用户查询
- `idx_tenant_ding_time`: (tenant_id, ding_user_id, start_at, end_at) - 按钉钉用户查询

**设计要点**:
- **多租户隔离**: tenant_id参与所有查询索引
- **幂等性**: 通过唯一索引保证同一审批实例不会重复插入
- **时间查询优化**: start_at和end_at建立复合索引，支持高效的时间重叠查询
- **姓名快照**: user_name字段存储请假时的用户姓名，即使用户改名也不影响历史记录
- **排障支持**: 保留原始JSON数据，便于问题排查

## 关键特性

### 1. 幂等性保证
- 使用 `(tenant_id, process_instance_id)` 唯一索引
- 支持钉钉重复回调和乱序回调
- 每次回调都会更新最新状态

### 2. 多租户隔离
- 所有查询都通过tenant_id隔离
- 使用TenantScopePlugin自动注入tenant_id
- 防止跨租户数据泄露

### 3. 异步处理
- Stream事件处理使用goroutine异步执行
- 避免阻塞Stream连接
- 提高系统吞吐量

### 4. 容错机制
- 解析失败不阻断流程，使用默认值
- 用户查找失败不阻断流程，userID为0
- 保留原始JSON便于排障

### 5. 灵活的表单解析
- 支持钉钉DDHolidayField组件
- 支持普通表单字段
- 支持多种字段名变体
- 支持多种时间格式

### 6. 姓名快照
- 存储请假时的用户姓名
- 即使用户改名也不影响历史记录
- 查询时无需JOIN user表，性能更好

## 性能优化

### 1. 索引优化
- 复合索引覆盖常用查询场景
- 时间范围查询使用索引
- 避免全表扫描

### 2. 批量查询
- `ListOverlappingByDingUserIDs` 支持批量查询多个用户
- 减少数据库往返次数

### 3. 异步处理
- 事件处理不阻塞Stream连接
- 提高并发处理能力

---

## 错误处理

### 1. 网络错误
- 钉钉API调用失败会记录日志
- 不影响其他审批实例的处理

### 2. 解析错误
- 表单字段解析失败使用默认值
- 记录警告日志但不阻断流程

### 3. 数据库错误
- 入库失败会返回错误
- 记录错误日志便于排查

## 总结

整个请假审批同步流程设计合理，具有以下优点：

1. **可靠性**: 幂等性保证、容错机制、异步处理
2. **性能**: 索引优化、批量查询、异步处理
3. **可维护性**: 清晰的分层架构、详细的日志、原始数据保留
4. **扩展性**: 灵活的表单解析、多租户支持、可扩展的架构

通过Stream模式实时接收审批事件，结合幂等性设计，确保了数据的准确性和一致性。
