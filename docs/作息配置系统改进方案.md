# 作息配置系统深度分析与改进方案

## 一、现状分析

### 1.1 当前系统架构

您的项目已实现了**双模式手动切换系统**：

**数据库设计：**
- `schedule_periods` 表：存储作息时段，包含 `mode` 字段区分上学/假期
- `schedule_settings` 表：存储每个租户当前激活的模式
- 上学模式：5个时段（第1-2节 至 第9-10节）
- 假期模式：3个时段（上午、下午、晚上）

**操作方式：**
- 管理员通过 API `/api/schedule/switch-mode` 手动切换模式
- 通过 GoAdmin 后台界面管理时段配置
- 多租户独立配置和切换

### 1.2 系统流程

```
管理员手动操作 → 调用切换API → 更新 schedule_settings 表
→ 考勤系统读取当前模式 → 使用对应时段配置计算考勤
```

## 二、核心问题识别

### 2.1 ⚠️ 人工操作风险

**问题：**
- 管理员必须记住在假期开始/结束时手动切换模式
- 人为疏忽可能导致考勤计算错误
- 没有提醒或通知机制
- 节假日前后容易遗忘操作

**影响：**
- 假期第一天忘记切换 → 使用错误的时段计算考勤
- 开学第一天忘记切回 → 考勤数据异常
- 需要事后手动修正数据，工作量大

### 2.2 ⏰ 缺乏时间维度

**问题：**
- 系统不知道每个模式应该在什么时间生效
- 无法提前规划未来的假期安排
- 没有模式切换的历史记录
- 无法追溯某个日期使用的是哪个模式

**影响：**
- 无法做年度作息计划
- 数据分析时难以关联时间段
- 审计困难

### 2.3 🔒 灵活性不足

**问题：**
- 只有两种固定模式（上学/假期）
- 无法处理特殊情况：
  - 考试周（可能需要特殊时段）
  - 假期中的培训班（需要上学模式）
  - 临时调整的作息时间
  - 周末与工作日的差异

**影响：**
- 特殊情况需要临时修改配置，容易出错
- 无法满足复杂的业务场景

### 2.4 🔗 与现有系统集成不足

**问题：**
- 已有 `semesters` 表包含学期的开始和结束日期
- 作息模式与学期生命周期没有关联
- 错失了自动化切换的机会

**影响：**
- 数据冗余（学期日期和作息切换日期需要分别维护）
- 容易出现不一致

## 三、改进方案

### 3.1 核心思路

**从"手动模式切换"转变为"基于日期的作息计划"**

不再是简单的"当前是什么模式"，而是"在指定日期范围内使用什么模式"。

### 3.2 方案设计

#### 方案A：扩展现有表（简单快速）

```sql
-- 为 schedule_settings 添加日期字段
ALTER TABLE schedule_settings
ADD COLUMN effective_date DATE NOT NULL DEFAULT CURRENT_DATE COMMENT '生效日期',
ADD COLUMN end_date DATE NULL COMMENT '结束日期（NULL表示无限期）',
ADD COLUMN auto_switch BOOLEAN NOT NULL DEFAULT TRUE COMMENT '是否自动切换',
ADD INDEX idx_tenant_dates (tenant_id, effective_date, end_date);
```

**优点：**
- 改动最小，快速实现
- 向下兼容现有代码

**缺点：**
- 只能存储一个计划，不够灵活
- 无法提前规划多个假期

#### 方案B：新建作息计划表（推荐）

```sql
CREATE TABLE schedule_plans (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  tenant_id INT UNSIGNED NOT NULL,
  mode VARCHAR(20) NOT NULL COMMENT 'school/holiday/custom',
  start_date DATE NOT NULL COMMENT '开始日期',
  end_date DATE NOT NULL COMMENT '结束日期',
  priority INT NOT NULL DEFAULT 0 COMMENT '优先级（数字越大优先级越高）',
  reason VARCHAR(200) COMMENT '原因说明（如：暑假、寒假、考试周）',
  created_by INT UNSIGNED COMMENT '创建人用户ID',
  is_active BOOLEAN NOT NULL DEFAULT TRUE COMMENT '是否启用',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted_at TIMESTAMP NULL,

  INDEX idx_tenant_dates (tenant_id, start_date, end_date),
  INDEX idx_tenant_active (tenant_id, is_active),

  CONSTRAINT chk_date_range CHECK (end_date >= start_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='作息计划表';
```

**数据示例：**

| id | tenant_id | mode | start_date | end_date | priority | reason |
|----|-----------|------|------------|----------|----------|--------|
| 1 | 1 | school | 2026-02-15 | 2026-07-10 | 10 | 春季学期 |
| 2 | 1 | holiday | 2026-07-11 | 2026-08-31 | 10 | 暑假 |
| 3 | 1 | school | 2026-09-01 | 2027-01-20 | 10 | 秋季学期 |
| 4 | 1 | holiday | 2026-10-01 | 2026-10-07 | 20 | 国庆假期 |

**优点：**
- 可以提前规划全年作息
- 支持多个计划并存
- 优先级机制处理重叠（如国庆假期覆盖学期）
- 保留历史记录，便于审计

**缺点：**
- 需要新增表和相关代码
- 实现复杂度稍高

### 3.3 核心功能实现

#### 功能1：自动模式检测

```go
// GetCurrentModeForDate 获取指定日期的作息模式
func (s *SchedulePeriodService) GetCurrentModeForDate(ctx context.Context, date time.Time) (string, error) {
    // 1. 查询该日期生效的所有计划
    plans, err := s.planRepo.GetActivePlansForDate(ctx, date)
    if err != nil {
        return "", err
    }

    // 2. 如果有多个计划，选择优先级最高的
    if len(plans) > 0 {
        // 按优先级降序排序
        sort.Slice(plans, func(i, j int) bool {
            return plans[i].Priority > plans[j].Priority
        })
        return plans[0].Mode, nil
    }

    // 3. 没有计划时，检查是否在学期内
    semester, err := s.semesterRepo.GetActiveSemesterForDate(ctx, date)
    if err == nil && semester != nil {
        return model.ScheduleModeSchool, nil
    }

    // 4. 默认假期模式
    return model.ScheduleModeHoliday, nil
}

// GetCurrentMode 获取当前模式（今天）
func (s *SchedulePeriodService) GetCurrentMode(ctx context.Context) (string, error) {
    return s.GetCurrentModeForDate(ctx, time.Now())
}
```

#### 功能4：冲突检测与预览

```go
// PreviewSchedule 预览指定日期范围的作息安排
// GET /api/schedule/preview?start=2026-07-01&end=2026-08-31
func (h *ScheduleSettingHandler) PreviewSchedule(c *gin.Context) {
    startDate := c.Query("start")
    endDate := c.Query("end")

    // 返回每一天的模式
    preview := []DaySchedule{}
    current := parseDate(startDate)
    end := parseDate(endDate)

    for current.Before(end) || current.Equal(end) {
        mode, _ := h.service.GetCurrentModeForDate(c.Request.Context(), current)
        preview = append(preview, DaySchedule{
            Date: current.Format("2006-01-02"),
            Mode: mode,
        })
        current = current.AddDate(0, 0, 1)
    }

    response.OK(c, preview)
}

// ValidatePlan 验证计划是否有冲突
func (s *SchedulePeriodService) ValidatePlan(ctx context.Context, plan *model.SchedulePlan) error {
    // 查询重叠的计划
    overlapping, err := s.planRepo.FindOverlappingPlans(ctx, plan.StartDate, plan.EndDate)
    if err != nil {
        return err
    }

    if len(overlapping) > 0 {
        // 返回警告信息，但不阻止创建（通过优先级解决）
        return response.NewBizError(response.CodeWarning,
            fmt.Sprintf("存在 %d 个重叠计划，将通过优先级决定生效顺序", len(overlapping)))
    }

    return nil
}
```

#### 功能5：定时任务与通知

```go
// ScheduleCheckJob 每天检查作息模式是否正确
func (s *Scheduler) ScheduleCheckJob() {
    c := cron.New()

    // 每天凌晨1点检查
    c.AddFunc("0 1 * * *", func() {
        ctx := context.Background()

        // 获取所有租户
        tenants, _ := s.tenantRepo.ListAll(ctx)

        for _, tenant := range tenants {
            tenantCtx := tenantctx.WithTenantID(ctx, tenant.ID)

            // 检查今天的模式
            expectedMode, _ := s.scheduleService.GetCurrentMode(tenantCtx)

            // 检查3天后的模式变化
            futureMode, _ := s.scheduleService.GetCurrentModeForDate(
                tenantCtx,
                time.Now().AddDate(0, 0, 3),
            )

            if expectedMode != futureMode {
                // 发送通知：3天后将切换模式
                s.notifyModeChange(tenant, futureMode, 3)
            }
        }
    })

    c.Start()
}
```

```go
// 迁移脚本：将现有设置转换为计划
package main

func migrateToSchedulePlans() {
    // 1. 获取所有租户的当前设置
    var settings []model.ScheduleSetting
    db.Find(&settings)

    for _, setting := range settings {
        ctx := tenantctx.WithTenantID(context.Background(), setting.TenantID)

        // 2. 检查是否有活跃学期
        semester, err := semesterRepo.GetActiveSemester(ctx)

        if err == nil && semester != nil {
            // 3. 为学期创建上学模式计划
            plan := &model.SchedulePlan{
                TenantID:  setting.TenantID,
                Mode:      model.ScheduleModeSchool,
                StartDate: semester.StartDate,
                EndDate:   semester.EndDate,
                Priority:  10,
                Reason:    fmt.Sprintf("从学期迁移：%s", semester.Name),
            }
            db.Create(plan)
        } else {
            // 4. 没有学期，创建一个长期计划
            plan := &model.SchedulePlan{
                TenantID:  setting.TenantID,
                Mode:      setting.CurrentMode,
                StartDate: time.Now(),
                EndDate:   time.Now().AddDate(1, 0, 0), // 1年后
                Priority:  10,
                Reason:    "从现有设置迁移",
            }
            db.Create(plan)
        }
    }
}
```

### 简化方案：学期联动（最小改动）

如果希望最小化改动，可以采用这个简化方案：

```go
// 不新增表，直接基于学期判断
func (s *SchedulePeriodService) GetCurrentMode(ctx context.Context) (string, error) {
    // 1. 检查是否在活跃学期内
    semester, err := s.semesterRepo.GetActiveSemester(ctx)
    if err == nil && semester != nil {
        now := time.Now()
        if now.After(semester.StartDate) && now.Before(semester.EndDate) {
            return model.ScheduleModeSchool, nil
        }
    }

    // 2. 不在学期内，检查手动设置
    setting, err := s.settingRepo.GetByTenantID(ctx)
    if err == nil && setting.CurrentMode == model.ScheduleModeSchool {
        // 如果手动设置为上学模式，尊重手动设置
        return model.ScheduleModeSchool, nil
    }

    // 3. 默认假期模式
    return model.ScheduleModeHoliday, nil
}
```

**优点：**
- 零数据库改动
- 实现简单
- 立即可用

**缺点：**
- 无法处理学期内的假期（如国庆、五一）
- 无法提前规划
- 灵活性差
