# Schedule Server - 多租户排课考勤管理系统

## 1. 项目简介

Schedule Server 是一套面向教育/培训机构的**多租户排课考勤管理系统**，深度集成钉钉开放平台。主要功能包括：

- 课程表导入与管理（Excel/XLS 文件导入，全量覆盖）
- 按周/日/节次考勤统计与快照存储
- 请假审批同步与考勤扣减
- 学期与作息时间配置（上学/假期模式切换）
- 用户与部门的钉钉同步
- 个人休息日管理
- 管理员操作审计日志
- 钉钉 Stream 流式推送（回调接收）

系统采用 **B/S 架构**，后端基于 Go（Gin 框架）开发。前端可对接钉钉小程序、钉钉 H5 或独立 Web 应用。

## 2. 核心功能需求

### 2.1 用户与组织管理

| 需求 | 说明 |
|------|------|
| 钉钉单点登录 | 用户通过钉钉免登码登录，服务端换取钉钉身份后签发 JWT |
| 用户同步 | 批量从钉钉同步用户信息（含拼音索引），保持本地数据一致 |
| 部门同步 | 从钉钉拉取组织架构，存储为本地部门记录 |
| 角色权限 | 0=普通用户（仅可访问自己数据），1=管理员（租户级），2=超级管理员（预留） |
| 考勤参与 | 用户和部门可独立配置是否参与考勤 |
| 用户身份 | 支持多种用户身份类型（`user_types` 表） |

### 2.2 课程排班

| 需求 | 说明 |
|------|------|
| 文件导入 | 通过 Excel（.xls/.xlsx）导入用户课表，全量覆盖 |
| 格式转换 | 支持 .html 格式自动转换为 .xlsx 后解析 |
| 周次列表 | 周次以字符串存储（如 "1,2,3,5,8-10"），支持连续/离散周 |
| 学期关联 | 导入时自动关联当前激活学期，支持多学期归档 |
| 手动编辑 | 对单个课程进行增删改查 |
| 复制课表 | 将他人课表复制到自己名下 |

### 2.3 考勤统计

| 需求 | 说明 |
|------|------|
| 实时计算 | 根据日期、周次、节次计算「应到 = 候选人 - 有课人员」 |
| 请假扣减 | 当请假审批通过且与节次时间窗口重叠时，计入请假列表 |
| 快照存储 | 管理员可手动触发统计并持久化，用于历史查询 |
| 部门筛选 | 支持按部门 ID 列表过滤考勤范围 |
| 周排行 | 统计本周各用户考勤次数排行榜 |
| 考勤文本 | 生成群发用的考勤文本消息 |
| 代签功能 | 管理员可为指定用户补签某节次考勤 |
| 考勤开关 | 支持全局开关考勤功能（`AttendanceEnabled`） |
| 打卡集成 | 对接钉钉考勤打卡 API，获取用户上下班打卡记录（`OnDuty`/`OffDuty`） |

### 2.4 请假审批同步

| 需求 | 说明 |
|------|------|
| 回调接收 | 通过钉钉 Stream 流式推送接收审批事件，存入 `leave_approvals` 表 |
| 幂等处理 | 使用 `(tenant_id, process_instance_id)` 唯一约束保证幂等 |
| 时间窗口匹配 | 使用半开区间 [start, end) 与节次时间做重叠检测 |

### 2.5 学期与作息配置

| 需求 | 说明 |
|------|------|
| 学期管理 | 配置学期名称、起始日期、总周数；每租户仅一个激活学期 |
| 作息模式 | 支持上学（school）/假期（holiday）模式；考勤按当前激活模式计算 |
| 作息时段 | 每种模式下可配置多个时间段（节次名称、起止时间、排序） |
| 课表变更通知 | 课表导入/修改时通过钉钉工作通知推送变更详情给用户（`ScheduleChangeNotifyEnabled` 开关控制） |
| 迟到提醒 | 考勤统计后向未打卡用户发送钉钉工作通知（`LateNotifyEnabled` 开关控制） |

### 2.6 休息日管理

| 需求 | 说明 |
|------|------|
| 个人休息日 | 用户可设置固定休息的星期几（1-7） |
| 管理员查看 | 管理员可查看所有用户的休息日配置 |
| 休息日编辑权限 | 管理员可控制普通用户是否能自行修改休息日（`RestDayEditingAllowed`） |

### 2.7 审计日志

| 需求 | 说明 |
|------|------|
| 操作记录 | 自动记录管理员所有 API 操作（方法、路径、状态码、耗时、IP） |
| 系统日志 | 记录系统级错误日志（级别、调用位置、消息、堆栈） |
| 日志查询 | 管理员可分页查询审计日志 |

## 6. 数据模型概览

### 6.1 核心数据表（共 14 张）

| 表名 | 说明 |
|------|------|
| `tenants` | 企业租户（corp_id、钉钉 AppKey/AppSecret/AgentID） |
| `users` | 用户（钉钉 ID、拼音索引、角色、考勤状态） |
| `user_types` | 用户身份类型（名称） |
| `departments` | 部门（钉钉 dept_id、父部门、叶子标记、考勤状态） |
| `user_departments` | 用户-部门关联（多对多，复合主键） |
| `courses` | 课程（user_id、semester_id、周次列表、星期几、节次） |
| `semesters` | 学期（起始日期、总周数、激活标记） |
| `attendance_records` | 考勤快照（日期+节次，JSON 存储各类用户 ID 列表） |
| `leave_approvals` | 请假审批（钉钉流程实例 ID、时间范围、审批状态） |
| `schedule_settings` | 作息设置（当前模式、考勤开关、通知开关等） |
| `schedule_periods` | 作息时段（模式 + 节次名称 + 时间窗口 + 排序） |
| `user_rest_days` | 用户休息日（固定休息的星期几，1-7，可为空） |
| `audit_logs` | 管理员操作审计日志（方法、路径、状态码、耗时、IP） |
| `system_logs` | 系统错误日志（级别、调用位置、消息、字段 JSON、堆栈） |

### 6.2 关键字段说明

**`schedule_settings` 字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `current_mode` | string | 当前作息模式：`school` / `holiday` |
| `attendance_enabled` | bool | 考勤功能总开关 |
| `schedule_change_notify_enabled` | bool | 课表变更钉钉通知开关 |
| `late_notify_enabled` | bool | 迟到提醒通知开关 |
| `rest_day_editing_allowed` | bool | 普通用户是否可自行修改休息日 |

**`courses` 字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `day_of_week` | int | 星期几（1=周一，7=周日） |
| `section` | int | 节次（1-based，对应作息时段配置） |
| `week_list` | string | 周次字符串（如 "1,2,3,5,8-10"） |

### 6.3 租户隔离

所有带 `tenant_id` 字段的表均由 `repository/tenant_gorm_plugin.go` 自动过滤，无需手动编写 WHERE 条件。

## 8. 运行与部署

### 8.1 本地开发

```bash
# 1. 准备数据库（MySQL 8.0+）
# 2. 复制 configs/config.yaml.example -> configs/config.yaml 并填写配置
# 3. 运行
go run cmd/main.go
```

### 8.2 配置说明

```yaml
# configs/config.yaml 关键配置项
server:
  port: 8080

database:
  host: localhost
  port: 3306
  name: schedule_server

schedule:
  periods:           # 作息时段配置（用于节次时间窗口计算）
    - section: 1
      start: "08:00"
      end: "10:00"
```

### 8.3 生产部署

- 使用 `config_prod.yaml` 作为生产环境配置
- 推荐：Docker / Kubernetes 部署
- 日志输出至 `logs/app.log`，支持自动轮转（Lumberjack）

### 8.4 数据库迁移

启动时自动执行 `AutoMigrate`，迁移所有 14 张表。如需手动数据迁移，使用 `scripts/` 下的迁移脚本：

```bash
go run scripts/migrate_schedule_periods.go
go run scripts/migrate_holiday_periods.go
go run scripts/reset_admin_password.go
```

## 9. 关键业务规则

### 9.1 考勤计算公式

```
应到人数 = 候选人（status=1 的参与考勤用户）- 有课人员（当天该节次有课的用户）

请假判断：请假审批通过 AND 请假时间与节次时间窗口有重叠（半开区间 [start, end)）
```

### 9.2 课表导入规则

- 全量覆盖：导入时删除该用户所有旧课程，写入新课程
- 不支持部分更新，确保数据完整性

### 9.3 多租户隔离

- 所有主要实体均有 `tenant_id` 字段
- GORM 插件自动在 SELECT/INSERT/UPDATE/DELETE 中注入租户条件
- 系统级操作（如初始化租户）需显式跳过：`tenantctx.WithSkipTenantScope(ctx)`

### 9.4 钉钉 Stream 推送

- 通过钉钉 Stream SDK 长连接接收审批回调，无需公网回调 URL
- 异步处理回调事件，使用 `context.Background()`（不使用请求上下文）
- 请假审批结果存入 `leave_approvals` 表
