# 作息模式（上学/假期）使用说明

本说明基于当前代码实现，介绍如何配置与使用上学(school)/假期(holiday)两套作息，并在两者之间进行手动切换。

## 1. 功能概览
- 支持两套作息：
  - 上学模式：按节次配置（示例 5 个时段/节次）
  - 假期模式：上午/下午/晚上三段
- 可手动切换当前生效模式，影响依赖“当前时段”的业务（如考勤统计）。
- 多租户隔离：每个租户独立维护与切换。

## 2. 数据准备与初始化
### 2.1 自动迁移
应用启动时会自动迁移表结构（包含新增 `schedule_settings` 与 `schedule_periods.mode` 字段）。
- 位置：`inits/database.go:45-61`

### 2.2 为历史租户批量生成假期配置
- 脚本：`scripts/migrate_holiday_periods.go`
- 作用：
  1) 将缺失 `mode` 的旧 `schedule_periods` 记录标记为 `school`
  2) 为每个租户插入 `holiday` 模式的三个时段（上午/下午/晚上）
  3) 初始化 `schedule_settings`（默认 `school`）
- 运行：
```bash
# Windows PowerShell/CMD 均可
go run scripts/migrate_holiday_periods.go
```

## 3. 后台（GoAdmin）管理
### 3.1 作息时间配置
- 路径：`/admin/info/schedule_periods`
- 列表/表单已支持“模式（mode）”字段，可筛选/选择 `school` 或 `holiday`
- 时间字段存储格式：`HH:MM:SS`（例如 `08:00:00`）

### 3.2 当前作息模式设置
- 路径：`/admin/info/schedule_settings`
- 选择当前生效模式：`school` 或 `holiday`
- 建议仅管理员可编辑该表

## 4. API 使用
所有接口位于 `/api` 下并受 JWT 鉴权保护。

### 4.1 获取完整作息信息
- `GET /api/schedule/info`
- 返回：当前模式、当前生效时段、两套模式的启用时段
- 示例（节选）：
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "current_mode": "school",
    "active_periods": [
      {"name": "第1-2节", "start": "08:00", "end": "09:40"}
    ],
    "school_periods": [...],
    "holiday_periods": [
      {"name": "上午", "start": "08:30", "end": "12:00"},
      {"name": "下午", "start": "14:00", "end": "18:00"},
      {"name": "晚上", "start": "19:00", "end": "21:00"}
    ]
  }
}
```

### 4.2 获取当前模式
- `GET /api/schedule/current-mode`
- 示例：
```json
{
  "code": 0,
  "message": "success",
  "data": { "current_mode": "school" }
}
```

### 4.3 切换当前模式（管理员）
- `POST /api/schedule/switch-mode`
- 请求体：`{ "mode": "school|holiday" }`
- 校验：目标模式必须存在“启用”的时段，否则返回业务错误
- 示例：
```bash
curl -X POST -H "Content-Type: application/json" \
     -H "Authorization: Bearer <JWT>" \
     -d '{"mode":"holiday"}' \
     http://localhost:26665/api/schedule/switch-mode
```

## 5. 典型流程
A. 首次启用假期作息
1) 启动服务（触发自动迁移）
2) 运行迁移脚本生成假期时段与设置
3) GoAdmin 检查：
   - `/admin/info/schedule_periods`（确认已有 `holiday` 三段且启用）
   - `/admin/info/schedule_settings`（默认 `school`）
4) 通过管理员在后台或调用 API 切换至 `holiday`
5) 依赖业务从 `GET /api/schedule/info` 获取实际生效时段

B. 手动维护作息
- 新增/编辑时段时务必选择正确的 `mode`
- 仅 `is_active=1` 的时段会在当前模式下生效
- 排序：`sort_order` 越小越靠前

## 6. 权限与缓存建议
- `POST /api/schedule/switch-mode` 建议仅管理员可调用
- 若系统对时段有缓存，切换模式后需要清理相关缓存（视实现而定）

## 7. 时间与格式
- 存库：`HH:MM:SS`（如 `08:00:00`）
- API 返回：去秒展示（`HH:MM`）
- 代码处理：`trimTimeSeconds` 截断秒

## 9. 常见问题
- 切换失败提示“目标模式暂无作息配置”：
  - 说明该模式下没有任何启用的时段；请先在 GoAdmin 补齐并启用
- `/api/schedule/info` 的 `active_periods` 为空：
  - 当前模式下启用时段为空，或数据库为空且 fallback 配置为空
