# 考勤调度器动态配置 - 代码逻辑总结

本总结概述重构后与“方案一”一致的核心运行逻辑与关键设计点，便于快速理解整体行为与后续联调。

## 变更范围
- 新/改文件：
  - `internal/scheduler/attendance_scheduler.go`（重构，支持多租户动态配置/回退/周期重载）
  - `internal/app/app.go`（更新依赖注入，传入 period/setting 仓库至调度器）
  - 相关已存在模块复用：
    - `internal/repository/schedule_period_repository.go`（按当前模式拉取租户作息段）
    - `internal/repository/schedule_setting_repository.go`（获取/切换模式）
    - `internal/service/attendance_record_service.go`（统计并落库）
    - `internal/repository/tenant_repository.go`（租户列表/详情）

## 运行时主流程
1) 启动阶段（`AttendanceScheduler.Start()`）
- 创建 `cron` 实例（本地时区）。
- 首次加载所有租户的作息调度：`reloadAllTenantSchedules()`。
- 注册周期性重载任务：每 5 分钟执行一次 `reloadAllTenantSchedules()`，以使配置变更在 5 分钟内生效。

2) 全量重载（`reloadAllTenantSchedules`）
- 使用 `tenantRepo.ListActive(context.Background())` 取得所有活跃租户 ID。
- 逐个调用 `reloadTenantSchedule(tenantID)` 重建该租户的定时任务。

3) 租户级重载（`reloadTenantSchedule(tenantID)`）
- 构造带租户的上下文：`tenantctx.WithTenantID(context.Background(), tenantID)`（确保多租户隔离）。
- 读取当前模式下的活跃作息段：`schedulePeriodRepo.ListActive(ctx)`。
  - 失败或返回空时，走“配置回退”：`loadTenantScheduleFromConfig(tenantID)`（使用 `config.Schedule.Periods`）。
- 移除该租户旧的 cron 任务（避免重复触发）。
- 为每个作息段计算触发表达式并注册任务：
  - 计算 cron：`buildCronExpressionFromTime(period.StartTime)` 支持 `HH:MM:SS` 或 `HH:MM`；触发时间 = 上课时间 + `delayAfterClassStart`（默认 3 分钟）。
  - 通过闭包显式捕获 `tenantID/section/period`，避免循环变量陷阱。
  - 注册后的 `entryID` 存入 `tenantJobs[tenantID]`，用于下次重载移除。

4) 配置回退（`loadTenantScheduleFromConfig`）
- 当数据库配置不可用时，基于 `config.Schedule.Periods` 为该租户生成同样的定时任务集合（同样保存 `entryID`，下次可移除）。

5) 任务触发（`triggerAttendanceForTenant(tenantID, section, now)`）
- 构造租户上下文并读取租户信息与当前周：
  - `tenantRepo.FindByID(ctx, tenantID)`
  - `semesterSrv.GetCurrentWeek(ctx)`
- 组装 `dto.AttendanceDetailRequest{ Date, Week, Section }`。
- 调用 `attendanceRecordSrv.GetAttendanceDetail(ctx, req)` 获取统计结果；
- 成功后 `attendanceRecordSrv.SaveAttendanceRecord(ctx, result)` 落库（应保持幂等，适配多实例部署）。

## 依赖注入与协作
- `internal/app/app.go` 中 `startAttendanceScheduler()`：
  - 构建 Repository、`attendanceRecordSrv`、`semesterSrv`；
  - 使用：
    ```go
    scheduler.NewAttendanceScheduler(
      global.AppConfig.Schedule,
      repo.TenantRepo,
      repo.SchedulePeriodRepo,
      repo.ScheduleSettingRepo,
      attendanceRecordSrv,
      semesterSrv,
      global.Log,
    )
    ```
  - 启动后常驻运行，随服务优雅关闭而停止。

- Repository 协作关系：
  - `SchedulePeriodRepository.ListActive(ctx)` 内部通过 `ScheduleSettingRepository.GetByTenantID(ctx)` 获取当前模式（无则默认 `school`），再按模式与激活状态取排序后的作息段。
  - 切换模式由 `ScheduleSettingRepository.SwitchMode(ctx, mode)` 完成；调度器靠周期性重载自动生效（可选提供手动触发）。

## 关键设计与规范落实
- 多租户隔离：
  - 所有仓储调用均传递 `context.Context`；定时任务内使用 `tenantctx.WithTenantID(...)`。
- 错误与降级：
  - 拉取作息段失败或为空时对单租户降级至 YAML 配置，不影响其他租户与整体运行。
- 时间解析：
  - 兼容 `HH:MM:SS`（数据库）与 `HH:MM`（YAML），统一转换为 `m h * * *` 的 `cron` 表达式。
- 变量捕获：
  - 循环注册 `cron` 时显式捕获临时变量，避免闭包引用同一地址导致的错位触发。
- 幂等性：
  - 多实例场景下可能并行触发统计；依赖 `SaveAttendanceRecord` 的唯一约束/幂等保证避免重复入库。
- 可观测性：
  - 全链路关键点打印结构化日志（租户、节次、cron 表达式、统计结果摘要）。

## 可选增强点
- 模式切换后主动调用 `scheduler.ReloadTenant(tenantID)` 缩短生效时间。
- 暴露健康检查接口，输出租户任务计数与下次重载时间。
- 结合缓存/版本号，精确判断是否需要重建任务，减少无效重载。
